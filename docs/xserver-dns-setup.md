# Xサーバー DNSレコード設定手順(fxlog.link-ai17.jp → Cloudflare Pages)

`link-ai17.jp`はXサーバーで取得済みのドメイン。FXログLPは**サブドメイン
`fxlog.link-ai17.jp`** で運用し、apex(`link-ai17.jp`)は将来別用途に
使う可能性を残すため**一切変更しない**。

**前提**: `docs/cloudflare-setup.md` の手順6で、Cloudflareの
Custom domain設定画面に表示された実際のDNSレコード内容(CNAME値)を
事前にメモしておくこと。以下は一般的な設定パターンの案内であり、
**Cloudflareの画面に表示された実際の値を優先する**こと。

## 1. Xサーバーアカウントにログイン

1. https://www.xserver.ne.jp/ の「ログイン」→「サーバーパネル」にアクセス。
2. Xserverアカウントの会員IDとパスワードでログインする。

## 2. ドメイン設定画面を開く

1. サーバーパネルのメニューから **ドメイン** → **ドメイン設定** を開く。
2. 対象ドメイン一覧から `link-ai17.jp` を選択する。

## 3. DNSレコード設定画面を開く

1. `link-ai17.jp` の設定画面内にある **DNSレコード設定** タブ(または
   同等のメニュー)を開く。
2. 「DNSレコード追加」のフォームを表示する。

## 4. fxlog.link-ai17.jp用のCNAMEレコードを追加する

サブドメイン運用のため、**apex用のAレコード設定は不要**。以下のCNAME
レコード**のみ**を追加する。

| 項目 | 設定値 |
|---|---|
| ホスト名 | `fxlog` |
| 種別(タイプ) | `CNAME` |
| 内容 | `<プロジェクト名>.pages.dev`(Cloudflareの画面で指示された実際の値をそのまま使用) |
| TTL | `3600` |

※ Cloudflareの画面で上記と異なる値・レコードタイプが指示された場合は、
必ずその指示に従うこと(本手順書はあくまで一般的なパターンの案内)。

## 5. 既存のapex DNSレコードには触れない

**重要**: `link-ai17.jp`(apex、ホスト名が空欄または`@`)に設定されている
既存のDNSレコード(Aレコード等)は、**本プロジェクト(FXログLP)の作業では
一切変更・削除しない**。apexは将来別用途で使う可能性があるため、現状維持
とすること。

今回追加するのは`fxlog`という新規サブドメインのCNAMEレコード1件のみで、
既存のapex向けレコードとは独立して共存できる。

## 6. TXTレコード(所有権確認用)

Cloudflareの画面で追加のTXTレコード登録を求められた場合(ドメイン所有権
確認等)は、指示された内容をそのままTXTレコードとして追加する
(この場合もホスト名は`fxlog`配下、または画面の指示通りにする)。

## 7. DNS反映の確認

DNSの反映には通常 **1〜24時間**、最大で **48時間** ほどかかる場合がある。

### 確認コマンド(ターミナル/コマンドプロンプト)

```bash
dig fxlog.link-ai17.jp
nslookup fxlog.link-ai17.jp
```

反映済みであれば、Cloudflareが指定したCNAME先(`<プロジェクト名>.pages.dev`)
が応答に含まれる。

### オンラインツール

- https://www.whatsmydns.net/ — `fxlog.link-ai17.jp` を入力し、世界各地の
  DNSサーバーでの反映状況を確認できる。
- https://www.ssllabs.com/ssltest/ — SSL証明書が正しく発行・設定されて
  いるかを確認できる(DNS反映後、SSL証明書発行まで完了してから使用)。
- whoisコマンド(`whois link-ai17.jp`)はドメイン自体の登録情報確認用
  であり、DNSレコード(サブドメイン)の反映確認には直接使えない点に注意。

## 8. SSL証明書の自動発行について

DNSレコードがCloudflare側に正しく反映されると、Cloudflare Pagesが
自動的にSSL証明書(Let's Encrypt または Google Trust Services)を
`fxlog.link-ai17.jp`向けに発行する。Xサーバー側・ユーザー側での追加の
SSL設定作業は不要。

証明書発行が完了すると、`docs/cloudflare-setup.md` 手順7の動作確認
(`https://fxlog.link-ai17.jp`へのHTTPSアクセス)が可能になる。

## トラブルシューティング

- **反映されない**: TTLの影響でキャッシュが残っている可能性がある。
  48時間経っても反映されない場合は、Xサーバー側の設定内容(ホスト名の
  タイプミス等)を再確認する。
- **SSL証明書が発行されない**: DNSレコードが正しく反映されているか
  `dig`コマンドで再確認する。CAA レコードが別途設定されていて
  証明書発行機関をブロックしていないかも確認する。
- **apexの既存サイトに影響が出た**: 本手順は`fxlog`サブドメインのCNAME
  追加のみで、apexの既存レコードには触れていないはずである。影響が
  出た場合は追加したレコードのホスト名が誤って空欄(apex向け)に
  なっていないか確認する。
